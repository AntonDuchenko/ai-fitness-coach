## 2. Не исправлено — по приоритету

### 🔴 Безопасность и деньги

1. **Нет rate limiting** нигде (`/auth/login`, `/auth/signup`, `/chat/send`, `/nutrition/*` с AI). Перебор паролей и сжигание бюджета OpenAI премиум-аккаунтом. → `@nestjs/throttler` глобально + жёстче на auth и AI-эндпоинтах.
2. **Нет защиты от двойной подписки:** премиум-пользователь может создать ещё один checkout → две активные подписки, двойное списание, чарджбеки. → В `createCheckoutSession` отказывать, если `isPremium`/активная подписка; отправлять в portal.
3. **Вебхуки вне порядка:** `customer.subscription.updated` может прийти раньше `checkout.session.completed` — `stripeCustomerId` ещё не записан, `updateMany` ничего не находит, событие помечается обработанным. → Класть `userId` в `subscription_data.metadata` и искать по нему; `subscriptionEndsAt` брать из `current_period_end`, хранить `cancel_at_period_end`.
4. **Токены в `localStorage`** (включая 30-дневный refresh). Любой XSS = кража сессии на месяц. Нет CSP/security-заголовков ни в Next, ни `helmet` в API. → httpOnly secure cookie для refresh, `helmet`, CSP в `next.config.js`.
5. **Refresh-токены нельзя отозвать:** нет ротации/хранения, logout только на клиенте, смена пароля не разлогинивает. → Таблица refresh-сессий (хэш + `revokedAt`), ротация с детекцией повторного использования.
6. **Health-эндпоинты** `/ai/health`, `/payments/health` доступны любому залогиненному и на каждый вызов дёргают платные внешние API. → Убрать под admin или кэшировать.
7. **Swagger открыт в проде** (`/api/docs`). → Включать только при `NODE_ENV !== "production"`.

### 🔴 Здоровье пользователей (юридический риск для фитнес-продукта)

8. **Расчёт калорий/макросов** (`users.service.ts`), задокументировано тестами `it.failing`:
   - Нет нижней границы калорий: женщина 45 кг / 150 см / 60 лет / 0 тренировок / похудение → **612 ккал/день**.
   - Отрицательные углеводы: женщина 120 кг / 160 см / 50 лет / похудение → **carbs = −44 г**.
   - Белок 2.2 г/кг от *общего* веса — для людей с ожирением завышен (лучше от целевого веса / сухой массы).
   → Минимум (обычно 1200 ж / 1500 м), clamp углеводов ≥ 0 с перераспределением, белок от целевого веса. Числа — продуктовое решение, поэтому не менял сам. После фикса убрать `.failing` из тестов.
9. Медицинские данные онбординга (болезни, лекарства) хранятся в `localStorage` и **не очищаются при logout** — на общем устройстве их увидит следующий пользователь. Аналогично черновики тренировок.

### 🟠 AI: стоимость и надёжность

10. **Токены и стоимость не записываются** (поля `tokens`/`cost` в `ChatMessage` есть, но всегда `null`). Без этого нельзя посчитать unit-экономику и цену подписки. → Сохранять `response.usage`.
11. **Двойные ретраи без таймаута:** OpenAI SDK по умолчанию делает 2 ретрая и ждёт до 10 минут, поверх — свои 3 ретрая → до 12 вызовов и HTTP-запрос, висящий минутами. → `new OpenAI({ maxRetries: 0, timeout: 60_000 })`.
12. **Выбор модели:** `gpt-3.5-turbo` (устаревшая) для «простых» сообщений, `OPENAI_MODEL` из env игнорируется в чате, модели захардкожены в 4+ местах. → Вынести в конфиг (`chatModel`, `planModel`).
13. **Нет стриминга ответов** — пользователь ждёт весь ответ 5–20 сек. Для чат-продукта это главный UX-фактор. → SSE.
14. **Ретрай джоба генерации неидемпотентен:** если упала генерация питания, ретрай заново генерирует уже готовый план тренировок (лишний gpt-4o). → Пропускать шаги, если активный план создан после старта джоба.
15. `getJobStatus` возвращает `complete`, если Redis не ответил за 3 с или джоб не найден → фронт показывает «планы готовы», которых нет.
16. In-memory кэш контекста не работает при >1 инстансе API; `truncateToTokenLimit` обрезает конец промпта — то есть именно **Guidelines** (язык, медицинский дисклеймер).
17. Свободный текст профиля (`injuries`, `medicalConditions`) вставляется в system prompt без экранирования — prompt injection (низкий риск, т.к. влияет на себя).

### 🟠 Бэкенд — прочее

18. Email не нормализуется (`User@x.com` и `user@x.com` — разные аккаунты).
19. Нет глобального exception filter — CLAUDE.md требует `{ statusCode, message, error }`, а необработанные ошибки Prisma (например, гонка на unique) отдаются как 500 без контекста.
20. `POST /workouts/log` не проверяет, что `workoutPlanId` принадлежит пользователю.
21. Сброс дневного лимита по таймзоне **сервера**, а не пользователя.
22. Нет эндпоинтов удаления аккаунта / экспорта данных — для health-данных это обязательное требование GDPR и App Store.
23. Нет observability: Sentry/OTel, request-id, структурированные логи.

### 🟡 Фронтенд

24. 163 из 176 `.tsx` — `"use client"`, включая лендинг. Server Components почти не используются → больший JS-бандл, хуже LCP/SEO лендинга (главный канал привлечения). → Секции лендинга без интерактива сделать серверными, анимации изолировать.
25. Нет `error.tsx` / `not-found.tsx` / `loading.tsx` ни на одном роуте; нет `middleware.ts` — защита роутов только на клиенте (мигание контента, лишние запросы).
26. Нет юнит-тестов хуков (`useAuth`, `useOnboardingSubmit`, `useWorkoutDraft`) — именно там бизнес-логика по правилам проекта.

### 🟡 Инфраструктура и репозиторий

27. **Нет CI** — ни линт, ни typecheck, ни тесты не проверяются автоматически. → GitHub Actions: `biome check`, `tsc`, `jest`, `next build`.
28. Нет Dockerfile / docker-compose (Postgres + Redis) — онбординг разработчика и деплой ручные.
29. 117 ошибок Biome (`pnpm lint:fix` исправит бо́льшую часть).
30. В git лежат артефакты: `*.tsbuildinfo`, PNG-скриншоты e2e, `.pen` на 1.5 МБ. → `.gitignore`, Git LFS.
31. SWC-билдер Nest компилирует `*.spec.ts` в `dist` (исключение в `tsconfig.build.json` для SWC не действует).
